# ai-context-memory

「忘れないAI」を段階的に作っていくPoCです。

## 現在の状態: MVP4（必要な記憶だけを検索して渡す）

「全記憶を毎回渡す」から「質問に必要そうな記憶を検索して、その結果だけ渡す」へ1段だけ進めた段階です。評価条件は [docs/mvp-04.md](docs/mvp-04.md) にあります。

- CLIでAIと会話できる
- 会話原文は `data/conversation.jsonl` へ保存する。これは証拠として残すだけで、再起動後に Claude へ再送しない
- ユーザー発言から抽出した長期記憶を `data/memories.jsonl` へ保存する（記憶抽出は MVP3 の方式のまま。対象はユーザー発言だけ）
- 全記憶を毎回 Claude へ渡すのをやめた
- 現在の質問から AI（Claude）が検索語を作り、Python が `memories.jsonl` を単純に文字列検索する
- ヒットした記憶だけ（最大5件）を、会話履歴とは別枠で回答用の Claude へ渡す
- 1件もヒットしなければ、1回だけ検索語を変えて再試行する（最大2ラウンド）
- ベクトル検索・embedding・全文検索エンジンはまだ使っていない。現段階の検索は単純な部分一致である
- 記憶の更新・矛盾解消はまだない
- Claude Code の呼び出し回数が増える。1ターンあたり通常3回（検索プラン作成・通常回答・記憶抽出）、検索が0件なら4回

これまでの段階:

| | 内容 |
|---|---|
| MVP1 | 履歴をメモリ上にだけ持つ「普通のAIチャット」。終了すると忘れる |
| MVP2 | 会話をファイルへ保存し、再起動時に全履歴を Claude へ再送する（[docs/mvp-02.md](docs/mvp-02.md)） |
| MVP3 | 会話原文と長期記憶を分離し、再起動後は長期記憶の全件を渡す（[docs/mvp-03.md](docs/mvp-03.md)） |
| MVP4 | AI が考えた検索語で長期記憶を検索し、ヒットした記憶だけを渡す |

## セットアップ

Python 3.10 以上と、ログイン済みの [Claude Code](https://claude.com/claude-code) CLI が必要です。

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -e ".[dev]"
```

LLMの呼び出しには `claude` コマンドを非対話モード（`claude -p`）で使います。APIキーは不要で、Claude Code にログインしているサブスクリプションの利用枠を消費します。

```powershell
claude auth status   # "loggedIn": true, "authMethod": "claude.ai" なら準備完了
claude auth login    # 未ログインの場合
```

環境変数 `ANTHROPIC_API_KEY` / `ANTHROPIC_AUTH_TOKEN` が設定されていても、このアプリは `claude` に渡しません（渡すとAPI課金になるため）。

## 起動方法

```powershell
python -m ai_context_memory
```

`exit` または `quit`（もしくは Ctrl+C / Ctrl+Z → Enter）で終了します。

```text
チャットを開始します。終了するには exit または quit と入力してください。

あなた> 私の名前はテスト太郎です

AI> テスト太郎さん、はじめまして。
[記憶] ユーザーの名前はテスト太郎

あなた> exit
終了します。
```

`[記憶]` は、その発言から長期記憶として保存した内容です。

再起動すると、長期記憶を検索対象として読み込みます。前回の会話そのものも、記憶の全件も Claude へは渡しません。質問のたびに検索し、ヒットした記憶だけを渡します。

```text
長期記憶を読み込みました（4 件）。
チャットを開始します。終了するには exit または quit と入力してください。

あなた> 私の名前は？
[検索] 名前 / 氏名
[検索結果] 1件

AI> テスト太郎さんです。

あなた> 私の血液型は？
[検索] 血液型
[検索結果] 0件
[再検索] O型 / A型 / B型
[検索結果] 0件

AI> 血液型については記録が見当たらず、覚えていません。

あなた> 1+1は？

AI> 2です。
```

`[検索]` は AI が考えた検索語（複数あるときは ` / ` 区切り）、`[検索結果]` はヒットした記憶の件数です。過去の記憶が不要だと AI が判断した発言では、検索しません。

使用モデルは Claude Code 側の既定モデルです。環境変数 `ACM_MODEL` で変更できます（`claude --model` に渡せる値）。検索プラン作成・通常回答・記憶抽出のすべてに同じモデルを使います。

```powershell
$env:ACM_MODEL = "sonnet"
```

`claude` はツール無効・利用者設定（CLAUDE.md、MCP、フックなど）を読み込まないモードで起動するため、素のチャットとして動作します。1ターンごとに `claude` を3〜4回（検索プラン作成、0件なら検索語の再生成、通常回答、記憶抽出）起動するので、応答が表示されるまでと、表示されたあと次の入力ができるまでに、それぞれ数秒かかります。

## 保存するデータ

| ファイル | 役割 | Claude へ渡すか |
|---|---|---|
| `data/conversation.jsonl` | 会話原文。証拠 | 渡さない（追記するだけで、起動時に読み戻さない） |
| `data/memories.jsonl` | 抽出された長期記憶 | 起動時に読み込んで検索対象にし、検索でヒットしたものだけを別枠で渡す |

- 保存場所: 起動時のカレントディレクトリから見た `data/`（`chat.bat` から起動した場合はリポジトリ直下の `data/`）
- `data/` は `.gitignore` の対象で、Git管理対象外です。会話内容も記憶もGitHubへ公開されることはありません
- 会話もユーザーも1つだけです。最初からやり直すには `data/` の2つのファイルを削除してください
- 保存先は環境変数 `ACM_HISTORY_FILE` / `ACM_MEMORY_FILE` で変更できます

```powershell
$env:ACM_HISTORY_FILE = "D:\work\trial\conversation.jsonl"
$env:ACM_MEMORY_FILE = "D:\work\trial\memories.jsonl"
```

### 会話原文（conversation.jsonl）

- 形式: JSONL。1行が1メッセージ（`{"role": "user", "content": "..."}`）
- 保存タイミング: AIの応答が正常に返るたびに、user / assistant の1ターンを追記する。`exit` / `quit` やエラーになったターンは保存しない
- 保存に失敗した場合は、応答を表示したうえでエラーを表示し、会話を続行する（そのターンは原文が残らないので、記憶抽出も行わない）

MVP2 で保存した `conversation.jsonl` はそのまま残りますが、そこから記憶を作り直すことはしません。記憶になるのは MVP3 以降で会話した発言だけです。

### 長期記憶（memories.jsonl）

- 形式: JSONL。1行が1つの記憶

  ```jsonl
  {"text": "ユーザーの名前はテスト太郎", "origin": "user", "evidence": "私の名前はテスト太郎です"}
  ```

  | フィールド | 内容 |
  |---|---|
  | `text` | 記憶内容 |
  | `origin` | 誰の発言が元か。現段階では常に `user` |
  | `evidence` | 根拠となった原文。元のユーザー発言からの抜き出し |

- 抽出タイミング: 通常の応答が返り、会話原文を保存できたあとに、そのユーザー発言1つだけを入力として、別の `claude -p` 呼び出しで抽出する。AIの発言や過去の会話は抽出の入力に含めない
- 「それに決めます」のように、その発言だけでは意味が確定しないものは記憶されない
- ファイルが壊れている場合（手で編集して不正なJSONLになったなど）は、該当の行番号を表示して起動を中止する。ファイルを修正するか削除する

記憶抽出はチャット本体より優先度が低いので、抽出の呼び出しが失敗した、不正なJSONが返った、`evidence` の検証に失敗した、保存に失敗した、のいずれの場合も `[警告]` を表示して会話を続行します。AIが返した `evidence` が元のユーザー発言にそのまま含まれていない場合、その候補は保存しません（AIが根拠を作り出していないことの確認）。

## 記憶の検索

通常回答の前に、次の流れで記憶を検索します。

```text
検索プラン作成（AI） → 検索（Python） → ヒットあり → 回答（AI）
                                      → 0件 → 検索語を再生成（AI） → 再検索（Python） → 回答（AI）
```

### 検索プラン（AI）

現在のユーザー発言だけを別の `claude -p` 呼び出しへ渡し、過去の記憶が必要そうか、必要なら検索語を最大3個、JSONで返させます。検索語をPythonのルールで作ることはしません。

```json
{"needs_memory": true, "queries": ["名前", "氏名"]}
```

1回目が0件だったときだけ、元のユーザー発言と、0件だった検索語だけを渡して、別の検索語を考えさせます。

### 検索（Python）

`memories.jsonl` に対する単純な文字列検索です。

- 検索対象は各記憶の `text` と `evidence`
- 1つの検索語は空白区切りのキーワードで、キーワードをすべて含む記憶がヒットする。複数の検索語はどれか1つにヒットすればよい
- ヒットした検索語のキーワード数の合計をスコアにして、上位5件までを返す
- 英字の大文字小文字と全角・半角の違いだけはそろえる。読み・同義語・言い換えは考慮しない

言い換えや表記ゆれは検索側では吸収せず、AIが別の検索語を出すことに任せています。

### AIとPythonの役割分担

| 担当 | やること |
|---|---|
| AI | 過去の記憶が必要そうかの判断、検索語を考える、0件なら別の検索語を考える、検索結果を使って回答する。記憶抽出では、発言に後で役立ちそうな記憶があるかの意味判断 |
| Python | 記憶の読み込みと保存、検索プランや抽出結果のJSON検証、`evidence` の検証、`origin` の付与、検索実行、スコアリング、最大件数、同じ検索語の重複排除、検索ラウンドの上限、回答用の Claude へ渡す記憶の制御 |

検索はチャット本体より優先度が低いので、検索プランの呼び出しが失敗した、不正なJSONが返った、のいずれの場合も `[警告]` を表示し、記憶なしで回答へ進みます。記憶がまだ1件も無いときは、検索プランの呼び出し自体をしません。

### Claudeへ渡すもの

通常回答のたびに、今回の検索でヒットした記憶と、今回起動してからの会話を渡します。過去の `conversation.jsonl` 全文と `memories.jsonl` 全件は渡しません。

```text
[retrieved memories]
- ユーザーの名前はテスト太郎 (origin: user, evidence: 私の名前はテスト太郎です)
[/retrieved memories]

[user]
私の名前は？
```

システム指示で、これは「検索で取得した過去の記憶であり、現在の会話の履歴ではない」「保存されている記憶の全部ではない」「必要な場合にだけ使う」「現在の発言と矛盾したら現在の発言を優先する」「必要な情報が見当たらなければ推測せず、覚えていないと伝える」と伝えています。

## 現段階の限界

- 検索は部分一致だけなので、記憶の文面に現れない言葉で聞くと見つからない。例: 「ユーザーはヴェゼルに乗る予定である」という記憶は、「車は何に乗る予定だっけ？」では見つからない（記憶に「車」という語が無く、AIは答えである「ヴェゼル」を検索語にできない）
- 検索語を考えるAIには現在の発言しか渡さないため、「それは何インチ？」のように今の会話の流れに依存する質問では、適切な検索語を作れない
- 記憶は追記のみ。更新・取り消し・矛盾解消はなく、名前を言い直すと新旧両方の記憶が残る
- 重複排除は `text` の完全一致だけ
- 記憶に日時がないため、「今回の」のような相対的な表現がいつのことか分からなくなる
- 1ターンあたり Claude Code を3〜4回呼び出す（最適化していない）
- `claude` コマンドは、ログイン中のアカウントのメールアドレスと今日の日付を自動でモデルへ渡す。そのため、記憶以外の経路でユーザーに関する情報がAIに届くことがある

## テスト

```powershell
python -m pytest
```

テストは `subprocess` / Claude をモックして実行するため、`claude` を起動せず、利用枠も消費しません。保存先には pytest の一時ディレクトリを使うため、`data/` にも触れません。

## 構成

```text
src/ai_context_memory/
  llm.py       LLM呼び出し（claude CLIをsubprocessで実行するのはここだけ）。検索プラン作成・通常回答・記憶抽出
  chat.py      ChatSession: 現在の会話の保持、記憶の検索の制御、1ターンの送受信、記憶の抽出結果の検証と保存
  history.py   会話原文ファイル（JSONL）の読み込みと追記
  memory.py    長期記憶ファイル（JSONL）の読み込みと追記、記憶候補の解析と検証
  search.py    検索プランの解析と検証、長期記憶の文字列検索
  cli.py       対話ループ（入力・表示・終了・エラー表示）
  __main__.py  python -m ai_context_memory の入口
tests/
  test_chat.py / test_cli.py / test_history.py / test_llm.py / test_memory.py / test_search.py
```
