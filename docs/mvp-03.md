# MVP3: 会話原文と長期記憶の分離

## 目的

「会話原文」と「長期記憶」を分離する。

過去の会話全文を Claude へ渡さなくても、過去のユーザー発言から抽出した記憶だけを使って回答できることを確認する。

MVP2 は再起動後も答えられたが、実際には AI が記憶しているのではなく、過去ログを全部読み直しているだけだった。MVP3 で進めるのはこの1段だけで、賢い検索・記憶の更新・現在値管理は作らない。

| | 再起動後に Claude へ渡すもの |
|---|---|
| MVP2 | 過去の会話全文 |
| MVP3 | 過去のユーザー発言から抽出した長期記憶（会話全文は渡さない） |

## 成功条件

### 成功条件1: 名前（必須）

1. データを空にして起動する
2. 「私の名前はテスト太郎です」と入力する
3. 通常の AI 応答が返る
4. 会話原文が `conversation.jsonl` に保存される
5. 別途、長期記憶として「ユーザーの名前はテスト太郎」相当の情報が `memories.jsonl` に保存される
6. `exit` で終了する
7. 再起動する
8. 過去の `conversation.jsonl` は Claude への会話履歴として渡さない
9. 「私の名前は？」と聞く
10. 保存された長期記憶だけを使って「テスト太郎」と答えられる

### 成功条件2: 仕事の前提（手動確認・可能なら）

「今回の試験対象はAとBです。完了条件は両方成功することです」のように、最初に一度しか言わないが後まで必要な情報も記憶でき、再起動後に「今回の試験対象は？」へ答えられること。

このケースのための専用ロジックは作らない。成功条件1と同じ仕組みで通ることを確認する。

## 今回やらないこと

- SQLiteなどのDB
- RAG / ベクトル検索 / embedding
- 関連記憶だけを検索する仕組み、記憶同士の類似検索
- 記憶の分類体系の作り込み、fact / decision / candidate / task 等の本格的な型管理
- 古い情報の supersede / retract、最新値の決定、矛盾解消
- 同じ記憶の高度な重複排除
- 複数ユーザー、複数チャット管理
- GUI、Web検索
- deferred / pending の再浮上、イベント駆動、自動タスク実行
- 会話要約
- 過去会話全文の再投入
- Claude 呼び出し回数の最適化

## 仕様

### データ

| ファイル | 役割 | Claude へ渡すか |
|---|---|---|
| `data/conversation.jsonl` | 会話原文。証拠 | 渡さない（追記するだけで、起動時に読み戻さない） |
| `data/memories.jsonl` | 抽出された長期記憶 | 起動時に読み込み、全件を別枠で渡す |

`memories.jsonl` は JSONL（UTF-8）。1行が1つの記憶。

```jsonl
{"text":"ユーザーの名前はテスト太郎","origin":"user","evidence":"私の名前はテスト太郎です"}
```

| フィールド | 内容 |
|---|---|
| `text` | 記憶内容 |
| `origin` | 誰の発言が元か。MVP3 では常に `user` |
| `evidence` | 根拠となった原文。元のユーザー発言からの抜き出し |

- 保存場所は起動時のカレントディレクトリから見た `data/`。環境変数 `ACM_HISTORY_FILE` / `ACM_MEMORY_FILE` で変更できる。
- `data/` は `.gitignore` の対象で、どちらのファイルも Git 管理対象外。

### AI と Python の役割分担

| 担当 | やること |
|---|---|
| AI（`claude -p`） | このユーザー発言に、後で役に立ちそうな記憶があるかという意味判断。記憶候補（`text` と `evidence`）を JSON で返す |
| Python | 抽出結果の JSON 検証、`evidence` の検証、`origin` の付与、保存、読み込み、ファイル操作 |

Python が行う検証:

- 抽出結果全体が JSON 配列であること
- 各候補が `text` と `evidence` を空でない文字列として持つこと
- `evidence` が今回のユーザー入力に部分文字列としてそのまま含まれること。含まれなければその候補は保存しない
- `origin` は AI の出力を使わず、Python が `user` を付ける

### 記憶抽出

- 通常の AI 応答が正常に返り、会話原文を保存できたあとに、そのユーザー発言1つだけを入力として記憶抽出を行う。
- assistant の発言や過去の会話は抽出の入力に混ぜない。AI 自身の発言からは長期記憶を作らない（AI が自分で言ったことを記憶し、後で「以前決まりました」と自己増強するのを避けるため）。
- 「それに決めます」のように過去文脈がないと意味を確定できない発言は記憶しなくてよい。
- 記憶すべきものがなければ空配列 `[]` を返す。
- 抽出は通常回答とは別の `claude -p` 呼び出しで行う。そのため1ターンあたりの Claude 呼び出しは2回になる。
- 既に同じ `text` の記憶がある場合は追記しない（完全一致のみ。それ以上の重複排除はしない）。

### 通常回答時に Claude へ渡すもの

```text
[long-term memory]
- ユーザーの名前はテスト太郎
- 今回の試験対象はAとB
[/long-term memory]

[user]
私の名前は？
```

- 長期記憶: `memories.jsonl` の全件（検索・取捨選択はしない）
- 会話履歴: 今回のプロセスを起動してからの会話だけ
- 再起動前の会話全文: 渡さない

システム指示で次を伝える。

- 長期記憶は過去のユーザー発言から抽出されたもので、現在の会話中の発言ではない
- 現在の会話中に発言された内容だと誤認しない
- 必要な場合のみ使う
- 現在のユーザー発言と矛盾した場合は現在の発言を優先する

### エラー処理

記憶抽出はチャット本体より優先度が低い。次の場合は警告を表示して会話を続ける。

| 状況 | 動作 |
|---|---|
| 記憶抽出の Claude 呼び出しが失敗 | 警告を表示。そのターンの記憶は作らない |
| 抽出結果が不正な JSON | 警告を表示。そのターンの記憶は作らない |
| 候補の形式が不正、`evidence` が元発言に無い | 警告を表示。その候補だけ保存しない |
| `memories.jsonl` の保存に失敗 | 警告を表示。そのターンの記憶は作らない |
| 会話原文の保存に失敗 | MVP2 と同じ（応答とエラーを表示して続行）。証拠が残らないので記憶抽出は行わない |
| 起動時に `memories.jsonl` が壊れている | ファイル名と行番号を含むエラーを表示して終了。ファイルは変更しない |

## 評価方法

- 自動テスト（pytest）: `subprocess` / Claude をモックし、保存先は `tmp_path` を使う。再起動相当（新しい `ChatSession` を同じファイルで生成）で、古い会話全文がプロンプトに含まれず、長期記憶が含まれることを確認する。
- 手動スモークテスト: 成功条件1・2を実際の `claude` で実行する。
