# MVP2: 会話履歴のファイル永続化

## 目的

アプリ終了後も会話履歴を保持し、次回起動時に読み戻せること。

MVP1 は「終了すると忘れる」。MVP2 は「終了しても会話そのものは残る」。進めるのはこの1段だけで、賢い記憶は作らない。

| | 履歴の置き場所 |
|---|---|
| MVP1 | メモリ上の履歴だけ |
| MVP2 | メモリ上の履歴 + 終了後も残るファイル |

## 成功条件

1. 起動する
2. 「私の名前はテスト太郎です」と入力する
3. `exit` で終了する
4. アプリを再起動する
5. 「前回私が名乗った名前は？」と聞く
6. 「テスト太郎」と答えられる

## 今回やらないこと

- SQLiteなどのDB
- 会話要約
- 長期記憶の抽出・分類
- fact / decision / candidate 等への構造化
- RAG
- ベクトル検索
- 関連コンテキストだけを選ぶ処理
- 最新値・履歴の判定
- 複数会話・複数スレッド管理
- GUI
- Web検索
- Claude Code側のセッション永続化

## 仕様

### 保存形式と保存場所

- 形式は JSONL（UTF-8）。1行が1メッセージ。

  ```jsonl
  {"role":"user","content":"私の名前はテスト太郎です"}
  {"role":"assistant","content":"テスト太郎さん、はじめまして。"}
  ```

- 保存場所は、起動時のカレントディレクトリから見た `data/conversation.jsonl`。
  `chat.bat` はリポジトリ直下へ移動してから起動するので、常にリポジトリ直下の `data/` になる。
- 環境変数 `ACM_HISTORY_FILE` で保存ファイルを変更できる（手動検証で実データを汚さないため）。
- `data/` は `.gitignore` の対象とし、会話データをGitHubへ公開しない。
- 会話は1本だけ。ファイルも1つだけ。

### 起動時

- 保存ファイルを読み込み、`ChatSession` の履歴として復元する。
- 復元後は MVP1 と同じく、それまでの全履歴を毎ターン `claude -p` へ渡す。

### 保存タイミング

- ユーザー入力に対する Claude の応答が正常に返った時点で、user / assistant の1ターン（2行）を追記する。
- 応答が得られなかったターン（LLMエラー、中断）は保存しない。
- `exit` / `quit`、空入力は保存しない。

### エラー処理

| 状況 | 動作 |
|---|---|
| 保存ファイルがまだ存在しない | 空の履歴として起動 |
| 空ファイル | 空の履歴として起動 |
| 不正なJSONL（JSONとして壊れている、role / content が想定外） | ファイル名と行番号を含むエラーを表示して終了。ファイルは変更しない |
| 読み込み失敗（権限など） | エラーを表示して終了 |
| 保存失敗 | 応答は表示したうえで、保存できなかった旨のエラーを表示し、会話は続行 |

自動修復、バックアップ、リトライなどのリカバリ機構は持たない。

## 評価方法

- 自動テスト（pytest）: 保存 → 新しい `ChatSession` を生成 → 同じファイルから読み込み → 過去の user / assistant が復元され、LLM へ渡される、という「再起動相当」を確認する。実際の `claude` は呼ばず、保存先は `tmp_path` を使う。
- 手動スモークテスト: 上記「成功条件」の1〜6を実際の `claude` で実行する。
