# MVP4: 必要な記憶だけを検索して渡す

## 目的

長期記憶を毎回すべて Claude へ渡すのをやめる。

ユーザーの現在の質問から AI が検索語を考え、Python が `memories.jsonl` を検索し、ヒットした記憶だけを通常回答用の Claude へ渡す。

MVP3 は会話全文を渡さなくなったが、代わりに全記憶を毎回渡していた。記憶が増えれば、これもいずれコンテキストを圧迫する。MVP4 で進めるのはこの1段だけで、検索精度を極限まで上げることは目的にしない。

確認したいのは「全部持たせなくても、AI に探させれば必要な記憶へ辿り着けるか」。仮説は「検索エンジン自体を高度にしなくても、AI が検索語を考え直せるなら、単純な検索でもかなり使えるのではないか」。

| | 通常回答用の Claude へ渡す記憶 |
|---|---|
| MVP3 | `memories.jsonl` の全件 |
| MVP4 | 今回の検索でヒットした記憶だけ（最大5件） |

## 成功条件

### 成功条件1: 必要な記憶だけを渡す

`memories.jsonl` に次の複数の記憶がある状態で「私の名前は？」と質問する。

- ユーザーの名前はテスト太郎
- ユーザーはヴェゼルに乗る予定である
- ユーザーの好きな果物は梨
- ユーザーは冬タイヤを16インチで検討している

期待結果:

- AI が名前に関する検索語を作る
- Python が `memories.jsonl` を検索する
- 名前に関係する記憶だけ、または少数の検索結果だけが通常回答用の Claude へ渡される
- `memories.jsonl` の全件は通常回答用の Claude へ渡されない（ヴェゼル・梨・冬タイヤの記憶がプロンプトに入らない）
- 「テスト太郎」と回答できる

### 成功条件2: 検索語を AI に考えさせる

検索語を Python の固定ルールで生成しない。現在のユーザー質問を Claude に見せ、検索語を最大3個、機械的に解析できる JSON で返させる。検索語の表現そのものは固定しない。

### 成功条件3: 一度見つからなければ検索し直せる

1回目の検索で1件もヒットしなかった場合だけ、Claude にもう一度検索語を考えさせる。再試行は1回だけ（最大2ラウンド）。

```text
検索プラン作成 → 検索 → ヒットあり → 回答
                      → 0件 → 検索語を再生成 → 再検索 → 回答
```

## 今回やらないこと

- SQLite / FTS / ベクトル検索 / embedding / reranking / 外部検索ライブラリ
- 記憶同士の relation、記憶グラフ
- 記憶の更新、superseded、retract、現在値管理
- Working Memory / Task State
- 保存時の keyword / alias 付与などの検索用エンリッチ（topic / subject / aliases / keywords / relation / status も追加しない）
- 高度な重複排除
- AI 発言の記憶化
- 複数ユーザー、複数チャット
- GUI、Web検索
- MCP、Claude Code の本物の Tool Use 機能
- 無制限の検索ループ、本格的な Agent ループ
- Claude 呼び出し回数の最適化

記憶の保存形式と記憶抽出の流れ（通常回答 → 会話原文保存 → 記憶抽出 → 保存）は MVP3 のまま変えない。

## 検索方式

`memories.jsonl` に対する、Python だけの単純な文字列検索。

- 検索対象は各記憶の `text` と `evidence`。
- 検索語は空白区切りのキーワードとして扱う。1つの検索語に含まれるキーワードが**すべて**含まれる記憶がその検索語にヒットする（AND）。
- 複数の検索語は OR。どれか1つにヒットすれば結果に入る。
- スコアは「ヒットした検索語のキーワード数の合計」。スコアの高い順に並べ、同点は保存順。
- 上位5件までを返す。
- 比較の前に、英字の大文字小文字と全角・半角の違いだけをそろえる（NFKC + casefold）。それ以上の正規化（読み、活用、同義語）はしない。

キーワードを AND にしているのは、「ユーザー」のようにどの記憶にも現れる語が検索語に混ざっても、全件がヒットしないようにするため。表記ゆれや言い換えは、検索エンジン側ではなく、AI が別の検索語として出すことで吸収する。

## AI と Python の役割分担

| 担当 | やること |
|---|---|
| AI（`claude -p`） | 今の質問に過去の記憶が必要そうか考える。検索語を考える。0件なら別の検索語を考える。検索結果を使って最終回答する |
| Python | `memories.jsonl` の読み込み、検索プランの JSON 検証、検索実行、スコアリング、最大件数制御、同じ検索語の重複排除、検索ラウンド上限、通常回答用の Claude へ渡す記憶の制御 |

曖昧な探索戦略は AI、検索実行と制御は Python。

## 仕様

### 検索プランナー

通常回答の前に、別の `claude -p` 呼び出しで検索プランを作る。

1回目の入力は現在のユーザー発言だけ。

```text
[question]
私の名前は？
```

出力は JSON オブジェクトだけ。

```json
{"needs_memory": true, "queries": ["名前", "氏名"]}
```

「1+1は？」のように過去の個人的な記憶が不要な発言では、検索しない判断を返せる。

```json
{"needs_memory": false, "queries": []}
```

2回目（1回目が0件だったときだけ）の入力は、元のユーザー発言・前回使った検索語・0件だったという結果だけ。

```text
[question]
冬用のタイヤ、何インチで考えてたっけ？

[previous queries: 0 hits]
- 冬用タイヤ
```

### Python 側の制御

- 記憶が1件も無いときは検索するものが無いので、プランナーを呼ばない。
- プランが JSON オブジェクトであること、`queries` が文字列の配列であることを検証する。
- `needs_memory` が `false` なら検索しない。
- 検索語は空文字を除き、同じものをまとめ、先頭3個までを使う。
- 既に使った検索語は再検索しない。2回目のプランが使用済みの検索語だけだった場合は、検索せずに終える。
- 検索は最大2ラウンド。2回目も0件なら、記憶なしで回答する。

### 通常回答時に Claude へ渡すもの

```text
[retrieved memories]
- ユーザーの名前はテスト太郎 (origin: user, evidence: 私の名前はテスト太郎です)
[/retrieved memories]

[user]
私の名前は？
```

- 今回の検索でヒットした記憶だけ（最大5件）
- 今回の起動中の会話履歴と現在のユーザー入力
- 過去の `conversation.jsonl` 全文と `memories.jsonl` 全件は渡さない

システム指示で、これは検索で取得した過去の記憶であって現在の会話履歴ではないこと、保存されている記憶の全部ではないことを伝える。

### 検索ログ

検索を実行したときだけ、CLI に簡潔に表示する。複数の検索語は ` / ` で区切る。

```text
[検索] 冬用タイヤ
[検索結果] 0件
[再検索] 冬タイヤ / スタッドレス
[検索結果] 1件
```

### Claude 呼び出し回数

| 状況 | 1ターンあたり |
|---|---|
| 記憶がまだ1件も無い | 2回（通常回答・記憶抽出） |
| 通常 | 3回（検索プラン作成・通常回答・記憶抽出） |
| 1回目の検索が0件 | 4回（上記 + 検索語再生成） |

### エラー処理

検索はチャット本体より優先度が低い。次の場合は警告を表示し、記憶なしで通常回答へ進む。

| 状況 | 動作 |
|---|---|
| 検索プランナーの Claude 呼び出しが失敗 | 警告を表示。それまでのヒットが無ければ記憶なしで回答 |
| 検索プランが不正な JSON、形式が不正 | 同上 |

## 評価方法

- 自動テスト（pytest）: `subprocess` / Claude をモックし、保存先は `tmp_path` を使う。
- 手動スモークテスト: 複数の記憶を作って再起動し、「私の名前は？」と、保存した文面と少し違う聞き方（「冬用のタイヤ、何インチで考えてたっけ？」）を実際の `claude` で試す。見つからなかった場合も結果として記録する。
